We are moving RegImpact-SL towards final UAT and project closure.

## 2. Primary Acceptance Question

Can the existing RegImpact-SL application demonstrate the following workflow using authentic regulatory records, without relying on synthetic seed records?

1. An SME submits a business/product profile through the application.
2. The system constructs a meaningful regulatory retrieval query.
3. The retrieval system retrieves relevant authentic regulatory clauses.
4. The system identifies applicable approved regulatory rules.
5. The deterministic applicability engine evaluates the rules.
6. The system handles missing information and conditional requirements correctly.
7. The system produces an understandable decision-support result.
8. The result provides traceable regulatory evidence.
9. The SME can inspect the assessment through the actual frontend.

If this workflow is demonstrable, we can proceed towards final UAT.

Do not require the newly uploaded Gazette to have compiled successfully for this acceptance test. The existing approved authentic corpus is the intended basis.

### B. Retrieval Verification

Test the existing retrieval mechanisms:

- BM25.
- Dense retrieval.
- Hybrid RRF retrieval.

Use meaningful SME product/profile queries that correspond to actual regulatory documents.

Verify:

- Whether retrieved clauses originate from authentic documents.
- Whether their clause references are correct.
- Whether retrieval scores/ranks are genuine.
- Whether dense retrieval actually works in the running environment.
- Whether hybrid retrieval genuinely combines the available retrieval results.
- Whether the application reports the actual retrieval method used.

Do not claim that a retrieval mechanism works merely because its code exists.

If one retrieval method is unavailable, document it and determine whether the remaining working methods are sufficient for the core workflow.

### C. Deterministic Rule Execution

Inspect the existing approved authentic rules.

Select suitable real rules for testing.

Verify:

- Applicability evaluation.
- NOT_APPLICABLE handling.
- CONDITIONAL_MISSING_DATA handling.
- CONDITIONAL_RULE handling.
- UNSUPPORTED handling.
- Threshold and exception handling where relevant.
- Temporal applicability where implemented.
- Evidence linkage between executed rules and source clauses.

Do not manufacture scenarios or expected results.

Use existing genuine rule definitions and realistic SME profiles.

Clearly distinguish actual verified outcomes from test assumptions.

### D. End-to-End SME Workflow

The primary acceptance test must use the actual running frontend and backend.

Use the browser UI.

Do not replace the UI workflow with direct database insertion, direct API calls, CLI scripts, or manually constructed responses.

Test:

1. Open the SME application.
2. Enter or select a suitable business profile.
3. Submit a regulatory assessment.
4. Observe the retrieval process/result.
5. Inspect the applicable requirements.
6. Inspect exemptions or non-applicable rules where available.
7. Inspect missing-data or conditional outcomes where available.
8. Open the supporting regulatory evidence.
9. Verify that the result is understandable and traceable.

Capture screenshots and actual outputs.

If a step fails, record the exact failure. Do not silently bypass it.
